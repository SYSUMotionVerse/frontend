# 受试者知情同意书

使用现有 uni-app 界面和纯 JavaScript 笔画 PNG 生成。签名半屏覆盖导航、保留动画和重写/撤回/完成按钮；完成事件只携带裁剪 PNG 和比例，不传递 RGBA 大数组，也不调用原生视觉识别接口。关闭会放弃未验证修改，重新打开恢复最后一次通过服务端验证的笔画。

点击“完成”后调用 `POST /api/users/consent/verify/`，图片仅在识别服务内存中临时处理，不上传 COS、不创建签名或失败历史。用户只看到“处理中…”或要求重写的提示，不展示模型、网络或超时实现细节。

服务端使用免费自部署 PP-OCRv5 server 识别模型，保留 2 倍分辨率笔画，裁剪空白并补边，同时尝试整行识别和检测识别。文字须与登记姓名严格一致且置信度达到后台阈值。验证成功返回绑定用户、姓名、文档版本和图片摘要的签名凭据，客户端不能伪造识别文字放行。

完成阅读并勾选后，“确认签署并继续”调用 `/api/users/consent/submit/`。此时才保存正式 PNG、完整已签 PDF 和记录。提交错误保留已验证签名与请求 UUID，显示可读提示及请求编号，重试幂等；文档或姓名变化需重新确认。验证凭据默认 30 分钟有效。

同意书字段仍按页面实际显示尺寸计算，研究者默认李芳滨。正式签名保留实际图像比例并固定高度、左边缘；后台导出只含正式文件。

发布需先部署后端及内部 `consent_tools` 容器，再上传 `dist/build/mp-weixin`。前端源码与生产产物需执行原生识别调用零引用检查。真实手写姓名识别效果仍须用代表性样本测试，不能用印刷测试替代实际签名验收。
