# 2026-09-17 问卷浏览与跟练设备反馈

反馈设备：Huawei Nova14、鸿蒙 6.1、测试者报告微信 8.0.21。视频卡住时倒计时继续走，当前无法稳定复现。两张截图显示标签文字垂直偏移，以及交换主副画面后相机仍显示为小画面尺寸。

## 修复与证据

- **浏览返回循环（已定位）**：首页的问卷发现刷新将 `targetPage=questionnaire` 直接重定向，覆盖了浏览权限。现在保持首页及基线解锁提示，真正开始训练时仍执行基线门禁。回归覆盖首页 onShow 后不重定向、执行训练仍被拦截。
- **播放卡住（已修复可疑路径并增加恢复，未证明唯一根因）**：原 `canplay` / `loadedmetadata` 回调在已有进度时重复 seek，可能形成原生 seek/readiness 循环。现仅在切换视频/阶段或需要恢复源位置时定位；就绪与主副画面交换只同步播放状态。额外监测实际 `timeupdate` 的变化（包括循环回到零），8 秒不前进尝试 play，最多两次，继续无进度则进入现有错误及缓存回退路径。相同时间戳、重复 play 事件不会伪装成视频恢复。关闭自动播放与卸载时停止监测，不改变训练及音频计时。
- **相机尺寸（已定位适配缺口，需真机验证）**：竖屏过去只依赖百分比布局；现在测量相机 viewport，将实际像素尺寸通过既有 mediaSize 链传给原生 camera。布局切换后立即及延迟 120ms 复测，保留同一相机实例，避免重新初始化识别或录制。横屏继续使用原有明确尺寸。
- **文字位置（需真机验证）**：原生 cover-view 单行标签使用明确高度、相同行高及水平内边距，不再依赖 flex 与垂直 padding 计算文字位置。
